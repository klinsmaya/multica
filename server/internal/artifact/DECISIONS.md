# Decisions for the artifact slices landed so far (A00, A01, A03, A04, A05, A06, A07, A08, A09, A10, A11)

Baseline SHA: `18fa9f728a9e25f2465df2789631edb2a75442ad`. Behavior of today's attachments is recorded in `BASELINE.md`.

## In this change

- The revision record is six tables: `artifacts`, `artifact_revisions`, `artifact_blobs`, `artifact_uploads`, `artifact_operations`, `artifact_links`. A07 adds `artifact_edit_sessions`. A08 adds `artifact_events` and `artifact_event_receipts`. A10 adds `artifact_derivatives` for rebuildable office previews.
- No foreign keys. Workspace delete lists storage keys, deletes the rows in `DeleteWorkspaceArtifacts`, then calls `Storage.DeleteKeys` after commit. The same `storage.Storage` interface attachments already use receives the bytes.
- `head_revision_id` moves only in `CasArtifactHead`, and only when it is still the caller's base (`IS NOT DISTINCT FROM`, so the first revision matches NULL).
- `artifact_revisions` reject updates with a trigger. A new commit inserts a new row.
- Unique: `(artifact_id, revision_no)`, `source_upload_id` (where not null), `commit_operation_id`, `(workspace_id, actor_id, idempotency_key)`, `storage_key`. Title and filename are not unique.
- Same idempotency key and same request hash returns the stored revision. Same key and a different hash returns `IDEMPOTENCY_KEY_REUSED` and does not insert a revision. A stale `base_revision_id` records `REVISION_CONFLICT` on that operation and a retry of that same request returns the same conflict.
- Object keys for sealed bytes are `workspaces/{workspace_id}/artifacts/{blob_id}`. The filename is passed to `Storage.Upload` only as the content-disposition name.
- `artifacts_v1` defaults off (`FF_ARTIFACTS_V1`). While it is off, `MountArtifactRoutes` registers nothing and `/api/artifacts` is 404. While it is on, the same function mounts the read routes, the task-scoped submit routes, the text edit-session routes, and history restore behind `RequireArtifactsV1`: list by owner, metadata, revisions, revision content, preview, create, update, operation status, edit sessions, heartbeat, draft save, `POST /api/artifacts/{id}/restore`, static HTML/SVG preview, preview resources, and read-only Office preview (`GET .../office-preview`). `POST /api/upload-file` and `multica attachment` are unchanged. The flag is also published on `/api/config` so the issue sidebar can hide the Artifacts section. The CLI does not read the flag; `multica artifact` gets that 404 while the flag is off.
- A04 replaces A03's direct seal. `Commit` still uses the same request hash (artifact, base revision, sha256, size, declared media type, filename, source, task run). That hash does not include the upload id, so a retry peeks `artifact_operations` and returns the stored revision without opening a second upload. A consumed upload cannot seal another revision.
- Staging key is `workspaces/{workspace_id}/artifact-staging/{upload_id}`. The state path is `created → uploading → uploaded → verifying → scanning → ready`, then `committed` inside the same CAS transaction as the revision. `rejected`, `expired`, and `cancelled` drop the staging object. Verify checks size, the server-computed sha256, and a sniffed media type. A generic sniff (`text/plain` or `application/octet-stream`) may keep a more specific declared type; a contradicting specific sniff rejects the upload. Declared media type and filename are part of the immutable upload binding.
- The scanner is an interface on `Service`. A nil scanner uses `NopScanner`, which returns clean immediately. That is an explicit no-op, not a timeout. `ScanPending` and a scanner error leave the upload in `scanning` and do not seal. `ScanRejected` rejects the upload and does not create a revision. The sealed blob records `scan_status = clean` only after that pass. There is no malware-scanner vendor in this slice.
- A wrong `base_revision_id` still returns `REVISION_CONFLICT` and does not move head. The ready upload becomes `conflict_draft` with `expires_at` seven days out, and the staging object stays. The upload's base cannot be retargeted; a new head needs a new upload. `ExpireUploads` deletes overdue staging for one workspace. Nothing schedules it.
- Quota is a reservation check under `pg_advisory_xact_lock` for the workspace: open upload `expected_size_bytes` (states `created`, `uploading`, `uploaded`, `verifying`, `scanning`, `ready`, `conflict_draft`, and not yet expired) plus committed revision bytes. The ceilings are `DefaultWorkspaceArtifactQuotaBytes` (1 GiB) and `DefaultActorArtifactQuotaBytes` (256 MiB) unless the service fields are set. This is not a ledger. A14 owns settlement, refunds, and cross-workspace accounting.
- Seal copies the staging object to the blob key while the artifact row is locked, re-reads the sealed object, and requires the same size and sha256. The database transaction rolls back and the sealed object is deleted when CAS or a later insert fails. The staging object is deleted only after the transaction commits, so a conflict or a rollback does not drop a verified candidate. Local and S3 storage here have no object-lock ACL; deleting the staging key is what makes that URL unreadable. The row keeps `staging_key` because the binding is immutable.
- A05 reads do not return `storage_key`, `staging_key`, or a public object URL. List is `GET /api/artifacts?owner_scope=&owner_id=` inside the caller's workspace. Metadata, revisions, content, and preview load the artifact by id and then require workspace membership, the same 404 shape attachments use for a missing row and a non-member. `artifact_links` are not consulted, so a link does not grant access.
- Revision content is a private authenticated download (`Cache-Control: private, no-store`) with `Content-Disposition`. Range uses the attachment proxy, including 206 on a single byte range. HTML and SVG (`text/html`, `application/xhtml+xml`, `image/svg+xml`, and those extensions) on the content route are `application/octet-stream` with `Content-Disposition: attachment`, `X-Content-Type-Options: nosniff`, and `Content-Security-Policy: sandbox; default-src 'none'`. The preview route returns JSON only. `active_content` stays false.
- Markdown, text, CSV, PDF, and image/audio/video use the same kind names the attachment viewer already has. The issue sidebar section is behind `artifacts_v1` and lists title, filename, revision, updater, time, and status for `owner_scope=issue`. When the preview JSON has no `static_preview_path`, HTML and SVG stay escaped source text. Existing comment attachments are not copied into `artifacts`.
- Comment and chat messages have no `artifact_id` or `revision_id` column. An artifact card on a message is deferred until that pointer exists. This slice does not add one and does not backfill attachments.
- A06 adds `multica artifact` beside `multica attachment`. The commands are `create --task --file --title`, `update <artifact_id> --base --file`, `get <artifact_id> [--revision]`, and `status --operation`. Each prints JSON with `artifact_id`, `revision_id`, `operation_id`, and `state`. Create and update are `POST /api/artifacts` and `POST /api/artifacts/{id}/revisions`. Both require a task token (`X-Actor-Source=task_token`). The token's task must exist in the workspace and its agent must match `X-Agent-ID`. Create's `task_id` form field must equal that task, or the handler returns 403. The artifact is `owner_scope=task` and `owner_id` is the task. Bytes go through `artifact.Service` staging, verify, scan, and seal. The server generates the idempotency key as `task:<lowercase task uuid>:<uuid>`. Source is `agent`. Actor and created-by are the agent. `task_run_id` is the task id. A failed first commit deletes the artifact row when `head_revision_id` is still null. Responses never include `storage_key`.
- A07 adds one open lease per artifact for Markdown, TXT, JSON, and CSV (`md`, `markdown`, `txt`, `json`, `csv`, or media `text/markdown`, `text/x-markdown`, `text/plain`, `application/json`, `text/csv`). HTML and SVG stay out and return `NOT_EDITABLE` (415) with no session row. `POST /api/artifacts/{id}/edit-sessions` returns the lease token once and a fencing token. The token is stored as a sha256 hex hash. Fencing is `max+1` for that artifact. The session's `base_revision_id` is the head re-read under the artifact row lock. `editor_type` is `agent` for a task token and `human` otherwise. A second open lease returns `LEASE_HELD` (409). An elapsed open row is marked `expired` first, and its `draft_ref` stays.
- A draft is not a revision. `PUT /api/artifact-edit-sessions/{id}/draft` writes `workspaces/{workspace_id}/artifact-drafts/{session_id}` and does not move head. The cap is 1 MiB of UTF-8. Heartbeat and draft require the holder, the raw lease token, and the fencing token. A mismatch for another actor is 404. An expired or committed session is `LEASE_EXPIRED` (409). Heartbeat extends the lease by two minutes.
- Formal save is still `POST /api/artifacts/{id}/revisions`. Optional form fields `edit_session_id`, `fencing_token`, and `lease_token` are all required together. With none of them, the A06 task-token path is unchanged. `If-Match`, when present, must equal `base_revision_id` or the handler returns `REVISION_CONFLICT` before staging. The lease is checked inside the existing artifact-row lock, before a ready upload is kept and again before CAS. DB CAS remains the overwrite guard. A valid lease with a stale base still records `conflict_draft`, then marks the session `expired` and leaves `draft_ref`. An expired or already-committed fencing token cannot submit. A new lease re-reads head and copies that actor's latest `draft_ref` onto a new key. Other actors do not receive it. Draft objects are not deleted on expire, conflict, or a failed copy.
- A presented lease lets a member who can already read the artifact commit as `human_edit`. The filename stays the head revision's filename. Without a lease, a human still cannot update (403). An unexpired open lease rejects a leaseless commit, including the agent CLI, with `LEASE_HELD`. No open session leaves A06 as it was.
- A08 does not add a second candidate table. An agent or CLI formal commit that would move a head under an unexpired human lease, and that does not present that lease, still returns `LEASE_HELD` inside the artifact-row lock. It does not overwrite the head and it does not become `conflict_draft`. An elapsed open lease with no presented lease does not block, so the agent can commit after expiry and the new commit re-reads the head through CAS. A presented expired or already-committed fencing token still returns `LEASE_EXPIRED` and does not submit. Draft objects stay.
- Auto-merge runs only after the lease check has passed and the caller's `base_revision_id` is not the current head. Both sides must be recognized text (the A07 extensions and media types, not HTML or SVG) and at most 1 MiB of UTF-8. The line counts must match, and no line may have been changed to different text on both sides. The merged bytes are sealed as a new blob and CAS'd against the current head. `base_revision_id` stays the caller's ancestor. `parent_revision_id` is the head that was merged. Source stays the caller's source. Unequal lengths, overlapping lines, HTML, SVG, and anything else keep the existing `conflict_draft` path. Binary is not merged. The merged text is not scanned again.
- `POST /api/artifacts/{id}/restore` takes `{revision_id, base_revision_id}` and optional lease fields. It inserts a new revision with `source=restore`, the same `blob_id` as the chosen historical revision, and `restored_from_revision_id` set to that revision. Parent and base are the caller's current head. The historical row is not updated. CAS uses that head. A stale base returns `REVISION_CONFLICT` and the transaction rolls back, so no new row remains. An unexpired lease without the matching session, actor, hash, and fencing token returns `LEASE_HELD` and does not cancel the human lease. Permission matches a write: a member who can read may restore. A task token aimed at an artifact it does not own is 404. A non-member is 404. Anonymous is 401. Soft-deleted artifacts are 404. The operation key is `restore:<new revision uuid>`.
- `artifact_events` is written in the same transaction as create (`artifact.created`, revision and operation null), a successful seal, and a successful restore (`artifact.revision.committed` and `artifact.preview.ready`). The preview event is a stub emitted with the commit. A08 does not render HTML. Columns are `id`, `workspace_id`, `artifact_id`, `revision_id`, `operation_id`, `event_type`, and `created_at`. The row has no payload, file body, storage key, or download secret. An idempotent commit replay peeks the operation and does not insert another event. `ApplyEvent` inserts `artifact_event_receipts` with `INSERT ... SELECT ... ON CONFLICT DO NOTHING`. The first call for an event id returns applied. A repeat returns not applied. There is no push channel. The issue sidebar still loads artifacts through the authorized read API. Workspace delete removes receipts for that workspace's events, then the events.
- A09 adds `GET /api/artifacts/{id}/revisions/{rid}/static-preview` for a sealed HTML or SVG revision of at most 1 MiB. The handler reads the sealed blob, strips scripts, event handlers, forms, frames, embeds, and URLs other than a fragment `href`, and writes a fragment. XHTML is served as `text/html; charset=utf-8`. SVG is served as `image/svg+xml`. The content route still returns the original bytes as an attachment. A file over the cap omits `static_preview_path`. If the static preview GET fails, the sidebar shows the source text and the download. `active_content` stays false. There is no `allow-scripts` mode.
- The response CSP, content type, `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy`, and `frame-ancestors` are constants in `artifact.StaticPreviewCSP` and the headers next to it. User HTML cannot set them. A `<meta http-equiv="Content-Security-Policy">` in the file is dropped. `iframe sandbox` and `allow-scripts` do not block network by themselves. CSP is not a complete egress boundary. This slice combines the sanitizer, the URL rewrite, and the deny-by-default CSP. It does not add a network proxy or a separate host.
- The static preview URL is on the API host. A direct browser GET still sends the session cookie. The body does not echo that cookie, the response does not set a cookie, and the CSP sandbox does not grant the document script or `connect-src`. The workbench does not navigate an iframe at that URL. It fetches the sanitized fragment with the existing API client and puts it in an iframe with `sandbox=""` and `srcdoc`. That frame has an opaque origin. This is not a separate origin, and it is not cookie isolation for the initial API request.
- `GET /api/artifacts/{id}/revisions/{rid}/resources/*` accepts one package-internal path after `NormalizePackagePath`. Absolute paths, URLs, backslashes, and `..` are 400. A path that cleans to a registered manifest entry is the only path that could be served. A single HTML or SVG revision uses `SingleFileManifest`, which is empty, so a clean path is 404 and the handler does not read storage. `BuildManifest` rejects a symlink and two names that clean to the same path. Authorizing the HTML revision does not authorize another workspace file. A non-member is 404. Anonymous is 401.
- Go's sniffer reports a bare SVG as `text/plain` and an XML SVG as `text/xml`. `resolveMediaType` keeps a declared `image/svg+xml` for those two sniffs so a sealed SVG revision can exist. A PNG declared as SVG still fails. A DOCX, XLSX, or PPTX package sniffs as `application/zip`. `resolveMediaType` keeps those three declared types for that sniff. A zip declared as HTML still fails.
- A10 adds `artifact_derivatives`. A derivative is not a revision and not an attachment. One row per `(revision_id, format)`. Status is `pending`, `ready`, or `failed`. The object key is `workspaces/{workspace_id}/artifact-derivatives/{derivative_id}`. The filename is not part of the key. Workspace delete lists that key and deletes the rows. A ready row has a null `expires_at`. A failed row sets `expires_at` seven days out. Nothing deletes it. Seven days is an ops default, not a promise that a sweeper runs.
- A02 did not approve a converter. This slice does not add a Go module. The converter is the Go standard library (`archive/zip` and `encoding/xml`). It reads OOXML structure. It does not run macros or fetch URLs. LibreOffice is MPL-2.0 and can render a PPTX to PDF or images. It is not installed in this environment and it is not vendored. PPTX preview is slide text and a slide count. Image and PDF preview were not produced.
- DOCX page count is the number of explicit `w:br w:type="page"` breaks plus one. It is not a layout engine. XLSX preview is sheet names plus cell text. The derivative HTML is escaped and then passed through the A09 sanitizer, so the preview is not a lower security level than the static HTML preview.
- Conversion runs in a re-exec of this binary. `init` exits before the server opens a database, telemetry, or a listen socket. The child environment is an allowlist: `PATH`, `TMPDIR`, and `MULTICA_OFFICE_*`. It does not receive `DATABASE_URL`, a session cookie, `Authorization`, or proxy variables. `MULTICA_OFFICE_ALLOW_NETWORK` is `0`. The child does not write the database. A network namespace was not applied. The parent enforces a wall-clock deadline. The child sets `RLIMIT_CPU` and `RLIMIT_AS` when those limits are configured. Failure codes are `CONVERSION_TIMEOUT`, `CONVERSION_EXHAUSTED`, and `CONVERSION_FAILED`. The original revision stays on the content route.
- `GET /api/artifacts/{id}/revisions/{rid}/preview` for a DOCX, XLSX, or PPTX revision includes `office_status`, `office_error`, and, when ready, `office_preview_path`, plus page count, sheet names, or slide count. `GET .../office-preview` checks membership again and serves the sanitized HTML only when the derivative is ready. A non-member is 404. Anonymous is 401. A failed derivative is 404 on that route and still has a download on the content route. `active_content` stays false. The issue sidebar shows the preview when it is ready, a pending or failed state otherwise, and the download in every state.
- A11 audited web office editors before adding one. The choice is in the table below. OnlyOffice Docs Community Edition is AGPL-3.0. The vendor says an application that embeds that source must itself be released under AGPL-3.0, including a hosted service. That obligation is not acceptable for this repository. It is not added. Univer's core SDK is Apache-2.0. DOCX, XLSX, and PPTX import and export are Univer Pro, a commercial license, and new Pro purchases are paused. Pro is not added. Collabora Online source is MPL-2.0. A build of that source does not require a seat fee and does not relicense this repository. Their packaged CODE and COOL binaries add their own terms and are not vendored. LibreOffice is not installed here. A Collabora document server would be a second process that receives file bytes, with WOPI callbacks, an allowlist, and SSRF checks. That path is not this slice.

- The DOCX editor runs in the browser. Save serializes a DOCX here and posts it with the existing edit lease to `POST /api/artifacts/{id}/revisions`. A blob in the browser is not a saved revision. There is no document-server callback, so this slice adds no callback URL and no SSRF allowlist. The editor Help action that would open the vendor issue tracker with the page URL and the user agent is turned off. File Open in that menu does not load a different local file into the lease. No font resolver fetches a remote catalog.
- A DOCX head may open an edit session on the existing route. XLSX and PPTX stay on the A10 read-only preview and still return `NOT_EDITABLE`. HTML and SVG stay out. A DOCX draft is rejected. The text draft route is unchanged for Markdown, TXT, JSON, and CSV. Formal save is still the revision commit. The lease does not replace CAS.
- A DOCX with a macro part, a comments part, or tracked-change markup does not open a session. The response is `OFFICE_FEATURE_BLOCKED` (415). The download stays. A leased DOCX commit whose zip is missing a part name from the base revision returns `OFFICE_FEATURE_DROPPED` (409) and does not seal. Rewriting a part and keeping its name is allowed. Files over 20 MiB stay read only, the same cap as the A10 converter.
- `artifacts_v1` still defaults off. No new route is mounted.
- A task token cannot list or read the rest of the workspace. List is 404 unless `owner_scope=task` and `owner_id` is the token's task. Get, content, preview, revisions, and update are 404 unless the artifact is owned by that task. Status for a task token is 404 unless the operation actor is the token's agent and the idempotency key starts with that task prefix. A workspace member without a task token keeps the A05 reads and can read an operation in the workspace by id, and cannot create or update without a lease (403). Unauthenticated create is 401. Declared media type for the commit comes from the filename extension. HTML and SVG still download as an attachment octet-stream. Get with a revision id prints `state=committed`. Status maps `succeeded` to `committed`, a failed `REVISION_CONFLICT` to `conflict`, `failed` to `failed`, and `pending` to `pending`.

## Conflict with the plan

The plan's upload chapter separates presigned staging, an external scan, and a later seal. This slice keeps that order inside `artifact.Service`: bytes hit a private staging key, verify and the scanner run, then finalize copies into the immutable blob key. There is no second storage stack and no HTTP upload route. The copy holds the artifact row lock instead of a worker. `conflict_draft` retains the verified candidate for seven days on the row; the periodic delete is `ExpireUploads`, which A14 still has to schedule. A stale base is not rewritten onto the new head.

A03 had inserted the upload already `committed` and stored `scan_status = unchecked`. That shortcut is gone. Revision uniqueness, CAS, and the commit idempotency hash are unchanged.

The plan's office adapter is `open`, `exportDraft`, and `dispose`, and the client must not treat a blob as saved. This slice does that for DOCX only. The plan's callback rules apply when an independent document server posts a save. This slice has no such server. XLSX and PPTX editing remain out.
