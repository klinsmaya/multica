title: 템플릿 패키지 작성
description: 스킬, 에이전트, 스쿼드를 템플릿 마켓플레이스용으로 패키징하고 관리 콘솔에서 게시하는 방법.
---

템플릿 마켓플레이스는 Claude Code 플러그인 레이아웃의 **패키지**를 배포합니다. 패키지 하나로 스킬, 에이전트, 스쿼드를 한 번에 워크스페이스에 설치할 수 있고, 같은 패키지를 `claude plugin marketplace add`로도 쓸 수 있습니다.

이 페이지는 패키지를 작성하는 사람을 위한 것입니다. 운영자는 `/admin/registry`에서 게시하고, 워크스페이스 관리자는 **설정 → Plugins → 템플릿 마켓플레이스**에서 설치합니다. 둘 다 `plugins_v1`과 `marketplace_v1` 기능 플래그가 필요합니다.

## 레이아웃

```
customer-support-squad/
  .claude-plugin/plugin.json      # 필수
  README.md
  CHANGELOG.md                    # 버전의 변경 내역이 됩니다
  skills/<name>/SKILL.md          # Agent Skills 표준
  agents/<name>.md                # frontmatter + 지침
  .mcp.json                       # URL 서버만
```

디렉터리를 zip(최상위 폴더 포함 여부는 상관없음)으로 묶어 업로드합니다. 이 경로 밖의 파일은 아카이브에 남지만 Multica는 읽지 않습니다. `hooks/`와 `commands/`는 거부됩니다. 서버는 패키지 안의 코드를 실행하지 않습니다.

## plugin.json

```json
{
  "name": "customer-support-squad",
  "version": "1.0.0",
  "displayName": "Customer Support Squad",
  "description": "Triage and reply to support issues",
  "author": { "name": "Multica" },
  "keywords": ["support", "triage"],
  "metadata": {
    "multica": {
      "scopes": ["issues:read", "comments:write"],
      "squad": { "name": "Customer Support", "lead": "triager", "members": ["responder"] },
      "requires": { "runtime": "claude-code", "connectors": ["zendesk"] }
    }
  }
}
```

- `name`은 소문자(영문, 숫자, `.`, `_`, `-`)입니다. Multica 플러그인 키는 `<namespace>.<name>`, 예를 들어 `multica.customer-support-squad`가 됩니다.
- `version`은 semver입니다. 각 버전은 불변이며, 무엇이든 바꾸려면 새 버전을 게시합니다.
- `keywords`는 운영자가 따로 설정하지 않는 한 리스팅의 태그가 됩니다.
- 표준 필드 외에 Multica가 읽는 내용은 모두 `metadata.multica` 아래에 둡니다. 다른 소비자는 무시합니다.

### metadata.multica

| 필드 | 의미 |
| --- | --- |
| `scopes` | 패키지가 워크스페이스 관리자에게 요청하는 접근 권한으로, 플러그인 스코프 목록(`issues:read`, `comments:write`, `net:<host>` 등)에서 고릅니다. `.mcp.json` 서버에 대한 `net:` 스코프는 자동으로 추가됩니다. 스킬만 있는 패키지는 생략할 수 있습니다. |
| `squad` | 패키지의 에이전트로 만드는 스쿼드 하나. `lead`와 `members`는 `agents/`의 에이전트 이름입니다. `name`과 `description`은 선택입니다. |
| `requires` | 동의 화면에 표시될 뿐 강제되지 않습니다. `runtime`(에이전트가 작성된 런타임 종류), `min_backend`, `connectors`(연동 앱 id). |

## 스킬

`skills/<name>/SKILL.md`는 Agent Skills 표준을 따릅니다. frontmatter의 `name`은 디렉터리 이름과 같아야 하고 `description`은 필수입니다. 각 스킬은 설치가 소유하는 워크스페이스 스킬이 되며, 제거 시 삭제됩니다. 같은 이름의 스킬을 사람이 이미 만들었다면 설치가 실패합니다.

## 에이전트

`agents/<name>.md`는 Claude Code 에이전트 파일입니다. YAML frontmatter 뒤에 Markdown 지침을 씁니다.

```markdown
---
name: triager
description: Sorts incoming support issues by urgency and topic.
model: claude-sonnet-5-5
skills: [ticket-triage]
---

You are the first reader of every support issue…
```

Multica는 `description`, `model`, `thinking_level`, `skills`(같은 패키지의 스킬 이름)를 읽습니다. `tools`는 받아들이지만 무시합니다. 도구 접근은 허용된 스코프와 MCP 승인에서 나옵니다. 파일 이름이 워크스페이스에서의 에이전트 이름입니다.

에이전트는 **런타임 없이** 생성되며 모든 워크스페이스 멤버가 호출할 수 있습니다. 동의 화면에 이 점이 표시되고, 멤버가 각 에이전트 설정에서 런타임을 연결한 뒤에 작업을 배정합니다. 업그레이드 시 템플릿은 설명, 지침, 모델, 스킬을 다시 쓰고 런타임 연결, 아바타, 권한은 건드리지 않습니다. 새 버전에서 빠진 에이전트는 삭제가 아니라 보관되며, 다시 설치하면 복원됩니다.

## 스쿼드

`metadata.multica.squad`는 `lead`를 리더로, `members`를 멤버로 하는 스쿼드 하나를 만듭니다. 워크스페이스가 직접 추가한 멤버는 업그레이드 후에도 유지되고, 새 버전에서 빠진 에이전트는 스쿼드에서 빠집니다. 제거하면 스쿼드가 보관됩니다.

## MCP 서버

`.mcp.json`에는 원격 서버만(`{"type": "http", "url": "https://…"}`) 자격 증명 없이 적습니다. 각 항목은 에이전트가 트리거하는 MCP 훅이 되고 `net:<host>` 스코프가 추가되며, 도구는 설치 후에도 일반 MCP 승인 단계를 거칩니다.

## 게시

1. `/admin/registry/sources`에 `self` 또는 `official` 종류의 소스(예: `@self`)가 있는지 확인합니다.
2. `/admin/registry`에서 그 소스에 zip을 업로드한 뒤 리스팅 페이지에서 버전을 승인합니다.
3. 리스팅을 **게시됨**으로 바꿉니다. 공개 리스팅은 익명 `marketplace.json`에 나타나고, 그렇지 않으면 **공개 범위**를 편집해 소비자와 테넌트(Multica의 테넌트는 워크스페이스 id)를 고릅니다.
4. 이제 워크스페이스 관리자가 설정 → Plugins에서 템플릿을 보고 동의 화면을 통해 설치할 수 있습니다.

리스팅 페이지에는 각 버전의 내용(스킬, 에이전트, 스쿼드, MCP 서버)이 표시되어 검토자가 이름이 아니라 기능을 승인합니다.

## 시작 템플릿

새 레지스트리는 비어 있습니다. `make registry-seed`(또는 `server/`에서 `go run ./cmd/registry seed`)는 `server/internal/registry/seed/templates/` 아래의 패키지를 `@multica` 공식 소스에 불러와 승인, 게시, 공개하고 모든 Multica 워크스페이스에 배포합니다. 이 명령은 다시 실행해도 안전합니다. 기존 버전은 건너뛰고 운영자가 바꾼 공개 범위는 유지됩니다.

## Claude Code에서 마켓플레이스 사용

공개 API는 네임스페이스별로 표준 마켓플레이스 파일을 제공합니다.

```
claude plugin marketplace add https://<host>/registry/v1/@multica/marketplace.json
```

키 없이는 공개 리스팅만 보입니다. `/admin/registry/consumers`에서 만든 소비자는 API 키(`Authorization: Bearer rk_…`)를 받고 자신에게 배포된 항목을 봅니다.
